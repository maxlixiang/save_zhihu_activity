# codex可以100%正式接管所有编程工作了吗？

---

我也基本不手写代码了，几乎全由 [Claude Code](https://zhida.zhihu.com/search?content_id=767824647&content_type=Answer&match_order=1&q=Claude+Code&zhida_source=entity) 接管。
但你要问我是不是不用写代码——
从营销角度说，是的；
但实际上，一行代码都没少看，投入时间和手写时代差不多。
前提是：我经常用[happy](https://zhida.zhihu.com/search?content_id=767824647&content_type=Answer&match_order=1&q=happy&zhida_source=entity) 远程写代码，一些开源项目我是丢给它直接写完提交的，不过说实话实际这种个头不大的side project ，也是需要经常沟通细节和代码逻辑，更别说在大型项目上，自主决策质量始终不高，需要高强度对齐改动内容，远不是那种低强度的 vibe coding 就能胜任的。vibe coding 占比越高的地方，可替代性就越强，本身对人的要求就低，本质上更接近体力活。未来只会越来越强调即时交付，所谓的「轻松」，更多是一种阶段性的错觉。
我们是在既有系统上持续迭代，不能出问题，要考虑的变量也不少。
以前是：issue 里把任务一拆，讨论清楚接口和细节，各自开写。
现在变成：
先做完整的项目设计，在 [Obsidian](https://zhida.zhihu.com/search?content_id=767824647&content_type=Answer&match_order=1&q=Obsidian&zhida_source=entity) 的[claudian插件](https://zhida.zhihu.com/search?content_id=767824647&content_type=Answer&match_order=1&q=claudian%E6%8F%92%E4%BB%B6&zhida_source=entity)里通过对话和材料，让它尽量只优化格式，从已有资料和代码里整理细节，补充流程图，生成项目文档。agent只是用来当秘书的，不是帮我瞎编东西
再由 agent 拆任务进 issue 系统（我不做的拆给别人），按任务逐个生成 spec，最后再交给 coding agent 实施。
整个流程包括：前期准备、agent 执行、code review、人工验收。总体工作量其实变化不大。
问题在于，agent 一旦遇到复杂情况，往往会选择不太可靠的方案，需要对方案细节进行非常细致的约束。
（当然，整个过程我基本都通过命令行和周边系统打通，除了和 agent 对话，几乎没有额外操作。）
额外增加的，是对设计 / 计划 / 方案 / 实现等过程文档的系统化输出。
所以时间并没有省，但工程质量是提升的——以前这些事情被认为既浪费时间、又无法转化为绩效，索性不做。
现在更像是：我出方案，让“外包团队”执行，而且这个外包团队每次都给我新人，出了问题责任在我。
