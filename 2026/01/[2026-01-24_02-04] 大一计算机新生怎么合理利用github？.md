# 大一计算机新生怎么合理利用github？

---

很多大一新生对[GitHub](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=GitHub&zhida_source=entity)的理解，还停留在“一个全是英文、下载速度很慢、据说很牛逼的代码仓库”这个层面。有的同学甚至被老师或者学长忽悠着去学了一堆[Git命令行](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Git%E5%91%BD%E4%BB%A4%E8%A1%8C&zhida_source=entity)，什么`rebase`，什么`cherry-pick`，把脑子学成了一锅浆糊，结果连怎么在GitHub上找一个能跑通的项目都不知道。
但其实这玩意儿玩好了，你大学四年甚至以后的职业生涯，真的能少走太多弯路。
很多新生上来就想搞个大新闻，注册完账号，恨不得立马把自己写的那个控制台输出“Hello World”的C语言作业上传上去，甚至还想建个分支。
**千万别。**
GitHub最大的价值，首先不是给你存代码的（存代码你用网盘或者学校机房都行），它最大的价值在于它拥有全世界最优质的代码资产和学习路线。对于大一新生来说，你现在的段位是“青铜”，你要做的不是去打王者局，而是去观战。
简单说，就是学会“抄”。
这里的“抄”不是让你考试作弊，而是让你学会利用现成的轮子。在计算机这个行当，有一句至理名言：**不要重复造轮子。**
举个很具体的场景。大一你肯定要学C语言或者Python吧？老师布置了个大作业，让你写个“学生信息管理系统”或者“贪吃蛇”。你咋办？
一般同学：打开教材，对着那个满是灰尘的案例，一行一行敲代码，报错了就抓头发，搞了三天三夜，写出来一个界面丑得要死、一点就崩溃的程序。
会用GitHub的同学： 打开GitHub，搜索框输入：`student-management-system language:python` 或者 `snake-game language:c`。
你会发现新大陆。你会看到几百上千个别人已经写好的项目。这时候你不要随便点开一个就抄。你要看什么？看[Star](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Star&zhida_source=entity)（星星）的数量。这玩意儿就跟淘宝的好评数一样，虽然也有刷的，但大体上能反映质量。
找那个Star数比较高，但是更新时间又不太久远的（太久远的代码可能跑不起来，环境都变了）。点进去，先看[README.md](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=README.md&zhida_source=entity)。
记住，README是项目的门面。一个好的开源项目，哪怕只是个大作业，它的README也应该写得清楚明白：这玩意儿是干啥的，怎么安装，怎么运行，有哪些功能。
如果一个项目连README都没有，或者写得乱七八糟，直接关掉，看下一个。别浪费时间。
把你觉得不错的项目代码下载下来（那个绿色的Code按钮，Download ZIP），解压，在你的电脑上跑起来。这一步其实是最难的，特别是对于新生。你可能会遇到各种报错，比如“缺少库”、“环境变量不对”、“版本不兼容”。
但这正是你学习的最佳时机！这比你照着书敲代码有用一万倍。你要学会看报错信息，去复制那个报错，扔到谷歌或者百度（推荐谷歌）里去搜，或者直接在GitHub这个项目的Issues里搜。
当你费尽九牛二虎之力，把别人写好的贪吃蛇在你的电脑上跑起来的那一刻，你的GitHub入门就算是成功了一半。然后你再去读他的代码，看看他是怎么设计蛇的移动的，怎么判断撞墙的。这时候你再回去写自己的作业，那简直就是降维打击。
这叫什么？这叫“基于巨人的肩膀开发”。虽然听起来有点装，但实际上工作中我们大部分时间都在干这个事。**没有人会从0开始写一个操作系统，大家都是在改别人的代码。**
既然说了要“白嫖”，那怎么找资源就是个核心技能。GitHub的搜索框做得其实挺烂的，如果你只会输关键词，那搜出来的东西基本是大海捞针。
这块我得多说两句，因为太实用了。
你要找学习资料，别直接搜“Java教程”。你要搜 `awesome-java`。 记住 **[Awesome](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Awesome&zhida_source=entity)** 这个词。在GitHub上，有一种仓库专门收集各种资源列表，都以Awesome开头。比如 `awesome-python`，`awesome-machine-learning`，`awesome-cpp`。
这些列表里，汇集了该领域最顶级的库、框架、教程、书籍、工具。那是全世界的开发者一人一票投出来的精华。你大一迷茫，不知道学什么？把 `awesome-computer-science` 搜出来，那里面有完整的计算机科学自学路径，从数学基础到操作系统，从算法到网络，安排得明明白白。
如果你觉得那些列表太长太杂，想先快速建立一个扎实的底层认知，我也强烈建议你把 [全网累计下载100w+次的计算机基础知识手册](https://link.zhihu.com/?target=https%3A//mp.weixin.qq.com/s/igbCF4F-K0DJDxVrMJ9ViQ) 存下来。大一先把这个底子打好，后面看GitHub上的复杂项目也不会晕车。
再说个具体的。假设你想找一些练手的项目，但是又不想找那种几万个Star的工业级项目（太复杂看不懂），你想找点适合新手的。 你可以在搜索框里敲：`snake game stars:100..1000`。 这意思是，我要找贪吃蛇游戏，但是Star数量在100到1000之间的。这种项目通常有一定质量，但又不会复杂到让你怀疑人生，通常是个人开发者或者优秀学生的练手作，代码结构相对简单，最适合阅读。
再比如，我想找最近这一个月最火的AI项目，看看大家都在搞什么大模型。 你可以去 [Trending](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Trending&zhida_source=entity)（趋势）榜单看。这个榜单就是GitHub的热搜。每天去刷一眼Trending，比刷朋友圈有用多了。你能看到现在世界上最聪明的脑袋都在关注什么技术。如果全是AI，你就知道AI是风口；如果全是Rust，你就知道Rust在崛起。
这不需要你懂很多技术，这培养的是一种技术嗅觉。
### 关于Git命令行，那是后话
很多教程一上来就教你 `git init`, `git add`, `git commit`, `git push`。
我要唱个反调：**大一新生，先别死磕命令行。**
为什么？因为容易劝退。黑乎乎的窗口，输错一个字符就报错，不仅挫败感强，而且容易搞出事故。我见过太多新手，因为搞不清楚分支关系，一个 `git push -f` 把整个仓库覆盖了，那种绝望的眼神我至今难忘。
现在是202X年了，工具已经很进化了。
去下个 [GitHub Desktop](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=GitHub+Desktop&zhida_source=entity)，或者是 [SourceTree](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=SourceTree&zhida_source=entity)。这都是图形化界面的工具。拖拽一下就能上传代码，点一下就能同步。能用鼠标解决的问题，前期不要用键盘装X。
等你先把GitHub玩熟了，知道什么是Repo（仓库），什么是Commit（提交），什么是Branch（分支）之后，再去学命令行。这时候你就理解了，哦，原来那个按钮对应的就是这个命令。
等到你真正准备进阶，必须要在服务器上操作或者处理复杂协作时，你再直接看 [Git零基础实战手册](https://link.zhihu.com/?target=https%3A//mp.weixin.qq.com/s/YgN9lWGwcPw2qk9YJr7ngw)，它结合了一些大厂协作流程和事故案例，你需要知道在什么场景下该用什么组合，关键时刻能救命。
这就好比学开车，你得先摸方向盘，感受车怎么动，而不是先去背发动机的燃烧原理。
当然，作为计算机专业的学生，命令行最终是必须要掌握的，因为到了服务器上没有图形界面给你用。但在大一这个阶段，保持兴趣和成就感更重要。
说到这，得聊聊比较功利的话题了：就业和简历。
我现在招人的时候，简历上如果贴了GitHub链接，我是一定会点的。这比你的绩点、比你拿了什么校内三等奖要有说服力得多。
但是，大概有80%的求职者，GitHub点进去是惨不忍睹的。 我们要避免成为这80%：
1. **全是Fork：** 列表里几十个项目，全是从别人那Fork（叉）过来的，自己一个Commit都没有。这说明你只是个收藏夹管理员，不是开发者。
2. **全是空仓库：** 建了一堆项目，点进去只有一个 `readme` 说“这是我的练习”，然后半年没更新。
3. **甚至没有头像：** 顶着个默认头像，连个Bio（简介）都没有。
大一新生怎么经营自己的GitHub？把它当成你的技术博客和成长日记。
你可以建一个仓库，叫 `CS-Learning-Path` 或者 `Daily-Algorithm`。 你每天刷了一道LeetCode算法题，别写完就扔了。把代码整理好，写几句注释：这道题难点在哪里，我用了什么思路，时间复杂度是多少。然后上传上去。
坚持一年。 你知道这有多恐怖吗？ 一年后，你的GitHub上有365个绿色的格子（GitHub的贡献图）。面试官点进来一看，哇，这个孩子从大一就开始每天写代码，风雨无阻。这种自律和热情，比你代码写得有多精妙更打动人。
因为技术可以教，但是对编程的热情和坚持是教不出来的。
再说个案例。 前两年面过一个本科生，学校其实一般。但是他的GitHub上有一个项目，是他写的一个爬虫，专门爬取学校图书馆的空座位信息，然后推送到微信上。 代码其实写得挺烂的，很多地方甚至没做异常处理。但是！
1. 这个项目解决了实际问题（抢座难）。
2. 他有完整的文档，教同学怎么用。
3. 他有更新记录，记录了他怎么修复Bug，怎么适配学校网页的改版。
这就够了。这说明他具备了**发现问题 -> 动手解决 -> 持续维护**的完整工程师素质。我当时二话没说就给他过了。
所以，大一不要想着做大项目。做一个**能用的、解决了你自己痛点的**小工具。哪怕是一个自动帮你抢课的脚本（注意别违规哈），哪怕是一个帮你整理桌面文件的Python脚本。
### 参与开源？没那么高大上
很多人觉得“参与开源贡献”=“给Linux内核写驱动”或者“给TensorFlow优化算法”。 那是神仙干的事。
对于凡人，尤其是大一新生，参与开源的最佳路径是：**找茬**。
你在看别人的文档时，发现有个错别字；你在跑别人的Demo时，发现有个参数写错了；甚至你发现别人的中文文档翻译得像机翻一样不通顺。
这时候，你的机会来了。 点那个“Edit”按钮，把错别字改过来，发起一个 **Pull Request (PR)**。
这就算开源贡献！ 你别笑，很多大佬的第一次PR都是从改错别字开始的。 当你的PR被原作者Merge（合并）的那一刻，你的头像会出现在这个项目的Contributor列表里。那种成就感，真的会让你爽一天。
慢慢地，你可能会发现代码里的一个小Bug，试着修一下；再后来，你可能会觉得有个功能不顺手，试着加个几行代码。 一步一步来。不要想着一口吃成个胖子。
除了前面说的 `awesome` 系列，这几个资源你得看看：
1. **[Roadmap.sh](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Roadmap.sh&zhida_source=entity)**：这不是一个GitHub仓库，但GitHub上有很多类似的。它画出了后端、前端、DevOps、AI等各个方向的学习路线图。大一最容易迷路，跟着地图走，心里有底。
2. **[HelloGitHub](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=HelloGitHub&zhida_source=entity)**：这是一个专门推荐适合入门的、有趣的开源项目的月刊。对于不知道玩什么项目的新手极其友好，而且主要是中文语境，阅读障碍小。
3. **[Papers We Love](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=Papers+We+Love&zhida_source=entity)**：等你到了大二大三，开始接触核心课程了，这个仓库收集了计算机科学领域最经典的论文。读Paper是进阶的必经之路，早接触没坏处。
4. **[FreeCodeCamp](https://zhida.zhihu.com/search?content_id=766562195&content_type=Answer&match_order=1&q=FreeCodeCamp&zhida_source=entity)**：虽然它是个网站，但它的GitHub仓库也是宝藏。它是全球最大的免费编程学习社区，不仅有教程，还有很多实战项目。
再给你分享几个我的经验。
**1. 别做收藏党。** GitHub上有个功能叫Star。很多同学看到好项目，“啪”一个Star拍上去，心里想的是“先马后看”，实际上是“马了就不看”。 Star一时爽，看代码火葬场。 你可以Star，但请给自己定个规矩：每周周末，从自己的Star列表里挑一个项目，哪怕只花10分钟，看看它的代码目录结构也好。别让GitHub变成你的“松鼠症”仓库。
**2. 英语是道坎，得跨过去。** 我知道，看英文文档很头大。现在的浏览器翻译插件很强大，但我建议你：**逼自己看原版。** 计算机的一手资料全是英文。如果你依赖翻译，你永远比别人慢半拍，而且翻译出来的技术名词经常是错的。比如“Instance”翻译成“例子”还是“实例”，在技术语境下差别大了去了。如果一开始读不进去，可以先看一下这本[程序员必知必会英语手册](https://link.zhihu.com/?target=https%3A//mp.weixin.qq.com/s/nwTxZdRMdf93I9TTHWKE4g)。它专门提炼了技术文档里最高频的术语和句式，能帮你快速跨过看懂70%的那个门槛。坚持个半年，你会发现计算机英语其实就那几百个词来回倒腾。
**3. 别太迷信Star数。** 有些几万Star的项目，代码写得像屎山一样，完全是因为营销做得好或者赶上了风口。有些只有几百Star的项目，代码写得像诗一样优美。 怎么分辨？看代码的**规范性**。看它的变量命名是不是清晰，有没有注释，函数是不是太长。等你代码写多了，自然就有这种审美了。
**4. 社交属性别忘了。** GitHub全称是“全球最大的同性交友网站”（误）。它其实是个社交网络。 去Follow（关注）那些在这个圈子里活跃的大佬。比如尤雨溪（Vue的作者），比如Python之父。 不是让你去骚扰人家，而是看看人家在关注什么项目，人家给了什么项目Star。 大佬的眼光通常比你毒辣。跟着大佬的Star走，往往能发现下一个风口。
如果你将来想走科研路子，或者想做产品经理，GitHub的用法又不一样。
做科研/算法方向： 现在的论文，如果没有附带GitHub代码链接，可信度都要打折扣。 你想复现一篇CVPR或者ICML的论文，第一反应不应该是去死磕公式，而是去搜这篇论文有没有开源代码。 很多时候，公式里写得云山雾罩的参数，代码里就是一个具体的数字 `0.001`。 看代码比看论文懂那个算法要快得多。真的。 而且，你要学会用 Colab。很多AI项目现在的README里都会放一个“Open in Colab”的按钮。点一下，谷歌送你免费的GPU，直接在浏览器里就能跑大模型。对于大一学生那个破笔记本来说，这简直是福音。
做产品/全栈方向： 多关注 Issues（问题讨论区）。 这里是用户吐槽最多的地方。如果你想做一个开源产品，去看看竞品的Issues，看看用户都在骂什么。用户骂得最凶的点，就是你的机会。 比如某个库不支持某种格式，或者文档写得太烂。你把它解决了，这就是你的卖点。
不知不觉说了这么多。其实归根结底，GitHub就三个词：**搜索、阅读、记录**。
大一这个时候，大家都是一张白纸。有的同学可能已经开始在那焦虑什么“35岁危机”，什么“互联网寒冬”。 我觉得吧，少看点那种贩卖焦虑的文章。计算机依然是目前在这个星球上，普通家庭孩子能接触到的、最公平、天花板最高的行业之一。
而GitHub，就是你通往这个行业核心圈子的入场券。
不管你是想进BAT大厂，还是想去硅谷，或者想自己做个独立开发者，你的代码能力和开源视野决定了你能走多远。
别指望这玩意儿能让你一夜暴富。它就像健身一样，你今天传了一行代码，明天传了一行代码，感觉不到什么变化。但是当你坚持了一年、两年，回头一看，你会发现自己已经脱胎换骨了。
最后，给个小建议：今天晚上，别打游戏了。 去注册个GitHub账号（如果还没有的话），装个VS Code，把你的“Hello World”放上去。 然后，在个人简介里写上一句你想对自己说的话。
不管以后遇到什么Bug，遇到什么变态的需求，遇到多难搞的面试官，记得偶尔回来看一眼这个最早的仓库。 那里面藏着你的初心。
